FEATURED · CLIENT PROJECT

Enerfrog SQL ChatbotConversational analytics for energy and facilities

Facilities teams ask questions about their energy data in plain English and get answers that are correct 95% of the time, with no SQL needed.

Business question. A facilities team can ask which site had the highest average electricity usage in a given month. The supervisor extracts the utility type, reporting period and requested comparison from the question and conversation history, then routes the request to the relevant specialist.

SQL validation and retry. The query workflow loads the PostgreSQL schema and table relationships before generating SQL. For a usage comparison, it joins utility bills to facility records, filters by billing period and utility type, then groups and ranks facilities by average usage. An EXPLAIN step checks the query before execution and feeds errors back into a bounded retry loop.

Weather context and provenance. The weather workflow maps facilities to stations and aggregates heating and cooling degree days when a question calls for weather context. The answer includes source-record IDs so users can trace the result back to the underlying data.

CLIENT PROJECT · AI VOICE

Steadywell OSVoice automation for patient outreach and scheduling

An AI agent now makes 2,000+ appointment calls a month, cutting manual scheduling work by about 80%.

From scheduling event to call. Scheduling events trigger outbound calls for booking, confirmation or rescheduling. The FastAPI workflow records the call in PostgreSQL so the voice provider’s webhook can update the same record when the conversation ends.

Availability and follow-up. The scheduling integration uses Cal.com to look up open slots and create bookings. The backend classifies call outcomes and uses them to decide whether a follow-up is needed. Call windows and daily call limits constrain when the system can reach out.

CLIENT PROJECT · IN PRODUCTION

Dyre IDRanked health condition predictions for dogs and cats

The models are now in production with the client. In testing, for 92% of pets the actual condition appears in the model's top-10 risk list.

From records to model inputs. I used exploratory data analysis and preprocessing to turn veterinary and behavioural records into 30+ features for model training. The pipeline converts source observations into structured inputs the model can use to score candidate conditions.

Ranking and validation. The model returns a ranked shortlist of ten conditions for each pet. Top-10 accuracy measures whether the reference condition appears anywhere in that shortlist. Veterinary experts reviewed predictions before the client deployed the models.

PERSONAL PROJECT · RAG

LumenDocument Q&A with retrieval and reranking

Indexing and candidate retrieval. Documents are split into passages and embedded for similarity search. Hybrid retrieval combines keyword matches for exact terms with semantic matches for questions phrased differently from the source text.

Context selection and answer grading. A reranking step scores the retrieved passages against the question before the most relevant context is passed to the LLM. The answer is graded against the retrieved context before it is returned.

PERSONAL PROJECT · AGENTS

AI-HubOne local workspace for running coding agents

Agents in one place. A local web app that runs Claude Code and OpenAI's Codex CLI from a single interface, using the accounts you're already signed in to, with no API key needed. It detects installed agents automatically and shows their real model lists, effort levels, plan usage and credits.

Safe, switchable runs. Every run gets its own git worktree and branch, so the main code is never touched. A supervised mode asks for approval of each edit or command, and you can keep or discard a run's changes with one click. You can switch model, effort or agent mid-task, with a readable summary handed from one agent to the next.

Every run measured. A live activity feed shows messages and tool calls, alongside cost, time and tokens for each turn. After every turn it runs your test command, counts the lines changed and shows the result in a side-by-side Monaco diff view.

How a run works. Each task runs headless on its own aihub/run-<id> branch. The agent's output is converted into one shared event format, saved with event sourcing and streamed live to the UI. On an agent switch, the new agent gets the same worktree plus a handoff summary built from the event log, with a template fallback if the summary model fails. Optional API keys are kept in the OS keychain, never in the database or repo.
